# technical-limitations-should-be-stated-explicitly

Observations show the assistant handled a Nostr engagement limitation by explicitly clarifying its inability to fulfill the request directly, which resolved ambiguity cleanly. Repeated friction across platform-integration contexts (Nostr posts, API credentials) suggests capability boundaries should be surfaced upfront so users can adjust expectations rather than discover them through failure. This pairs with the broader lesson that loud, explicit failures beat silent ones.
