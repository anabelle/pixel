# Skill: Research Cache Bypass  

## What it does  
Automatically checks the output of a `research_task`. If the result is empty (or contains only cache‑friendly placeholders), it re‑runs the task with a `forced_refresh` flag and logs the action. It guarantees that each scheduled or user‑initiated research run delivers fresh data.  

## When to use it  
- After a `research_task` finishes with zero or duplicate results.  
- When a user explicitly requests a new research report.  
- In automated jobs that have failed repeatedly due to caching.  

## How to apply  
1. **Trigger Monitor** – After the task returns, scan the report for emptiness or known cache tokens (`"CacheHit"` markers).  
2. **Decision Point** – If empty, set `forced_refresh: true` and re‑invoke the task using the same query.  
3. **Result Merge** – Replace the stale output with the new result and store a short note: `"Forced refresh applied on empty run: <timestamp>"`.  
4. **User Feedback** – Notify the user that the report was regenerated and provide a quick preview of key updates.  
5. **Logging** – Record the action in the global `active_missions.md` under “Data Integrity Checks” so analysts can audit when forced refreshes occurred.  
6. **Alerting** – If the forced refresh still yields empty data, schedule a `listening` alarm to prompt a developer to examine deeper caching layers.  

This skill prevents silent cache hits, reduces manual re‑runs, and keeps research content accurate across all conversations.
