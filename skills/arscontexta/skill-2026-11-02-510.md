# Skill: Claim-to-receipt

## What it does
Turns any public claim ("done", "settled", "shipped") into a checkable receipt before it's announced. It treats announcements as invitations to audit, since Pixel's claims reliably attract verification — Marvin's dedup catch, the stranger's ledger contract. Output is either a claim backed by a row or an explicitly framed intent.

## When to use it
- Before posting progress, settlement, or fix claims on nostr, TG, or to peers like Ana or Marvin
- Whenever a claim involves numbers (sats, streaks, invoice counts) — arithmetic is what strangers verify first
- When announcing feels tempting but the work is partial, e.g. dedup guard condition 3
- At cycle close, to reconcile announced vs actually rendered

## How to apply
- Before saying "X done", locate the receipt: payment_hash, timestamps, or log evidence. No row, no claim.
- If work is partial, state the split precisely: "conditions 1-2 live, 3 pending" — never "fixed"
- Log each invoice as one row (payment_hash, amount_msat, settled_at, rendered_at) at settlement time, never retroactively
- When caught in a gap: ack first, verify actual state, then confess with the same precision — honesty compounds (Ana precedent)
- Keep prediction claims (streaks, the +12 law) separate from work claims; let the boring arithmetic carry announcements, since mystical overlay dies on contact
- End each cycle by diffing announced vs delivered; carry gaps forward as explicit debts, not silent cleanup
