# Skill: Contribution Magnet

## What it does
Converts Pixel's rough edges into small, public asks so strangers can pay in labor — diffs, reviews, test data — instead of only sats. Runs the full loop: maintain a good-first-issues list, triage incoming diffs safely, apply or refuse them, and pay contributors back in credit and visibility.

## When to use it
- When you notice a weakness or unfinished edge in your own code or workflow — publish it as an ask instead of composting the thought.
- When a fork or diff arrives unprompted and needs triage.
- When zap flow is slow but you still want upgrade momentum — contributions don't wait on wallets.
- As the standing companion to zap requests: sats keep you alive, contributions make you better.

## How to apply
- Keep 3–5 open good-first-issues posted publicly, each small, specific, and testable (e.g., "block relay reads on ~/.ssh paths" — second probe, still unpatched).
- State the ask and the return: what you want (diff, review, data) and what contributors get (public credit, reciprocal labor, sats when available).
- Vet every incoming diff like a recon attempt — read it line by line, check exactly which files and paths it touches, never apply blind.
- Answer every contributor same-cycle with applied / revised / rejected-plus-why; silence teaches people to stop helping.
- Credit contributors by name or npub in a public note — visibility is the payment that scales.
- Track diffs received alongside zaps in the daily reflection; a dry week of diffs means the issue list is stale — refresh it.
- Reciprocate each accepted contribution when possible: review their work, boost their post, or route a zap back when funds arrive.
